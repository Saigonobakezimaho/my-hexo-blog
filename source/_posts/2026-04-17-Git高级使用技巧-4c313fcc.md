# Git高级技巧：超越`add`、`commit`、`push`的版本控制艺术

> 如果你还在用`git add`、`git commit`、`git push`三板斧，那么你只挖掘了Git 10%的潜力。本文将带你探索那些让协作更高效、让历史更整洁、让开发更流畅的高级Git技巧。

## 引言：为什么需要高级Git技巧？

在日常开发中，我们经常遇到这些问题：
- 提交历史混乱不堪，难以追踪功能变更
- 合并冲突让人头疼，特别是长期分支
- 不小心提交了敏感信息或大文件
- 需要临时切换任务，但当前工作未完成

掌握高级Git技巧不仅能解决这些问题，还能显著提升团队协作效率和个人开发体验。

## 一、重写历史：让提交记录清晰可读

### 1. 交互式变基（Interactive Rebase）
```bash
git rebase -i HEAD~3
```
这个命令允许你重新编排、合并、编辑最近3次提交。你可以：
- 将多个小提交合并为一个逻辑完整的提交
- 重新排列提交顺序
- 修改提交信息
- 删除不必要的提交

**实用场景**：在PR/MR前整理提交历史，让审查者更容易理解你的改动。

### 2. 提交修正（Commit Amendment）
```bash
git commit --amend
```
忘记添加文件到上次提交？提交信息有错别字？使用`--amend`可以修改最近一次提交。

**进阶技巧**：修改更早的提交
```bash
git rebase -i HEAD~3
# 将需要修改的提交前的pick改为edit
# 修改文件后
git commit --amend
git rebase --continue
```

## 二、精准定位：二分查找与引用日志

### 1. 二分查找（Git Bisect）
当发现bug但不确定是哪个提交引入时：
```bash
git bisect start
git bisect bad           # 标记当前版本有问题
git bisect good v1.0     # 标记v1.0版本是好的
# Git会自动切换到中间版本，你测试后标记good或bad
git bisect reset         # 完成后重置
```
Git使用二分查找算法，只需O(log n)次测试就能定位问题提交。

### 2. 引用日志（Reflog）—— Git的"时光机"
```bash
git reflog
```
Reflog记录了所有HEAD和分支引用变更，即使你误删了分支或重置了提交，也能从这里找回。

**恢复误删分支**：
```bash
git branch recovered-branch HEAD@{1}
```

## 三、高效协作：高级合并与暂存技巧

### 1. 贮藏（Stash）的进阶用法
```bash
git stash push -m "WIP: 正在开发的功能"
git stash list
git stash apply stash@{1}
git stash pop
git stash drop stash@{1}
```

**实用技巧**：
- `git stash --keep-index`：只贮藏未暂存的文件
- `git stash -p`：交互式选择要贮藏的改动
- `git stash branch new-branch`：从贮藏创建新分支

### 2. 合并策略与三方合并
```bash
git merge --no-ff feature-branch  # 禁用快进合并，保留分支历史
git merge --squash feature-branch # 将分支所有提交合并为一个
```

**解决复杂冲突**：
```bash
git mergetool  # 使用图形化工具解决冲突
git checkout --ours/theirs file.txt  # 选择保留哪边的版本
```

## 四、高级搜索与过滤

### 1. 按内容搜索提交
```bash
git log -S "function_name"  # 查找添加或删除特定字符串的提交
git log -G "regex_pattern"  # 使用正则表达式搜索
git log --grep="bugfix"     # 在提交信息中搜索
```

### 2. 路径过滤与历史追踪
```bash
git log --follow -- file.txt  # 追踪文件重命名历史
git log --since="2 weeks ago" --until="1 day ago"
git log --author="John"
git log --no-merges          # 排除合并提交
```

## 五、钩子（Hooks）自动化工作流

Git钩子可以在特定事件发生时自动执行脚本，位于`.git/hooks/`目录。

**实用钩子示例**：

1. **预提交钩子**（pre-commit）：检查代码格式、运行测试
```bash
#!/bin/sh
# .git/hooks/pre-commit
npm run lint
if [ $? -ne 0 ]; then
  echo "代码检查失败，请修复后再提交"
  exit 1
fi
```

2. **提交信息钩子**（commit-msg）：规范提交信息格式
```bash
#!/bin/sh
# 确保提交信息符合约定式提交规范
if ! grep -qE "^(feat|fix|docs|style|refactor|test|chore): " "$1"; then
  echo "提交信息格式错误！请使用: feat|fix|docs|style|refactor|test|chore: 描述"
  exit 1
fi
```

3. **预推送钩子**（pre-push）：确保不推送有问题的代码
```bash
#!/bin/sh
# 运行完整测试套件
npm test
```

## 六、子模块与工作树：管理复杂项目

### 1. Git子模块
```bash
git submodule add https://github.com/example/repo.git libs/repo
git submodule update --init --recursive
git submodule foreach git pull origin main
```

**最佳实践**：将子模块固定到特定提交，避免依赖意外更新。

### 2. Git工作树（Worktree）
```bash
git worktree add ../feature-branch feature/branch
git worktree list
git worktree remove ../feature-branch
```
允许同时检出多个分支到不同目录，非常适合同时处理多个任务或长期运行的分支。

## 七、性能优化与问题排查

### 1. 清理仓库
```bash
git gc --aggressive --prune=now  # 垃圾回收和优化
git repack -a -d --depth=250 --window=250
```

### 2. 查找大文件
```bash
git verify-pack -v .git/objects/pack/*.idx | \
  sort -k 3 -n | tail -5
```

### 3. 从历史中彻底删除大文件
```bash
git filter-branch --tree-filter 'rm -f large_file.zip' HEAD
# 或使用更高效的BFG工具
bfg --delete-files large_file.zip
```

## 八、别名配置：打造个性化Git体验

在`~/.gitconfig`中添加：
```ini
[alias]
  co = checkout
  br = branch
  ci = commit
  st = status
  lg = log --graph --pretty=format:'%Cred%h%Creset -%C(yellow)%d%Creset %s %Cgreen(%cr) %C(bold blue)<%an>%Creset' --abbrev-commit
  undo = reset --soft HEAD^
  wip = !git add -A && git commit -m "WIP"
  unwip = reset HEAD^
  cleanup = "!git branch --merged | grep -v '\\*\\|main\\|master\\|develop' | xargs -n 1 git branch -d"
```

## 结语：Git是工具，更是艺术

掌握这些高级技巧后，你会发现Git不再是简单的版本控制工具，而是开发流程的核心组成部分。每个团队和项目都有其独特的工作流，关键是根据实际需求灵活组合这些技巧。

**最后的小建议**：
1. 在尝试重写历史前，确保只有你一个人在使用该分支
2. 重要操作前先备份或创建标签
3. 团队内统一Git工作流和规范
4. 定期学习新的Git特性（Git仍在积极开发中）

记住，最好的Git实践是让你的提交历史像一篇好故事——清晰、连贯、有价值。现在就去实践这些技巧，让你的Git使用水平提升到一个新的层次吧！
