# 前端工程化实践分享

最近在项目中深入研究了一下前端工程化的实践，想和大家分享一些经验和教训。简单来说，前端工程化就是借助工具和方法，让前端开发变得更加高效、规范和可维护。通过我在某个电商项目的实际操作，希望能为大家提供一些借鉴。

## 1. 编译与构建工具的选择

说到前端工程化，**构建工具**绝对是绕不开的一个话题。我们团队之前一直用的 Webpack，虽然功能强大，但配置起来真的有点复杂，尤其是当项目需求变得多样化时，一些小问题就能让人抓狂。于是我们决定尝试 Vite。

### Vite 的优点

- **快速冷启动**：Vite 基于 ES 模块，可以在开发中实现近乎即时的热更新，这让调试变得非常流畅。
- **配置简单**：Vite 的配置文件相对简洁，很多默认配置就能满足日常需求，不用再像 Webpack 那样一堆 loader。

用 Vite 构建的电商网站上，页面加载速度提升了不少，开发体验也大大提升。推荐大家试试，如果你还在用 Webpack，其实可以考虑逐步迁移。

## 2. 代码质量与规范

有了构建工具，接下来就是代码质量的问题。我们团队引入了 ESLint 和 Prettier。这两个工具可以帮助我们保持代码风格一致，避免因为小的语法问题影响开发效率。

### 实践中的具体步骤

1. **初始化项目**：

      npm install eslint prettier eslint-plugin-prettier eslint-config-prettier --save-dev
   
2. **创建配置文件**，然后在 `.eslintrc.js` 中添加如下配置：

      module.exports = {
       extends: ['eslint:recommended', 'plugin:prettier/recommended'],
       env: {
           browser: true,
           es6: true,
       },
       rules: {
           // 你可以根据需求自定义规则
           'no-console': 'warn',
           'eqeqeq': 'error',
       },
   };
   
3. **在 package.json 中添加脚本**：

      "scripts": {
       "lint": "eslint .",
       "format": "prettier --write ."
   }
   
通过这些基础配置后，每次提 PR 前，我们要求都先提交一次 `npm run lint` 和 `npm run format`，这样整个团队的代码质量保持在一个较高的水平，并且让代码风格统一。

## 3. 模块化与组件化

对于大型应用，模块化和组件化是前端工程化的重要一环。在这个电商项目中，我们使用了 Vue 作为框架，充分利用其组件化特性来进行开发。

### 组件化的好处

- **复用性高**：比如购物车、商品展示等功能，我们都是封装成独立的组件，这样在不同页面中可以直接复用。
- **便于维护**：组件独立后，当某个组件需要修改或者升级时，只需关注那个小部分，降低了维护的复杂度。

具体来说，我们在实现一个商品列表展示组件时，采用了以下结构：

<template>
    <div class="product-list">
        <ProductCard v-for="product in products" :key="product.id" :product="product" />
    </div>
</template>

<script>
import ProductCard from './ProductCard.vue';

export default {
    components: {
        ProductCard,
    },
    props: {
        products: {
            type: Array,
            required: true,
        },
    },
};
</script>

这样，每次更新产品的信息，都在 `ProductCard` 组件中进行，不会对商品列表造成影响。

## 4. 自动化测试

在开发过程中，测试的环节常常被忽略。我们引入了 Jest 来进行单元测试，确保代码逻辑的正确性。前期测试的投入虽然比较大，但后期的维护成本降低了，整个项目更易于扩展。

### 设置 Jest

1. **安装 Jest**：

      npm install --save-dev jest vue-jest @vue/test-utils
   
2. **创建测试文件**，如 `ProductCard.spec.js`：

      import { shallowMount } from '@vue/test-utils';
   import ProductCard from './ProductCard.vue';

   describe('ProductCard.vue', () => {
       it('renders props.product when passed', () => {
           const product = { id: 1, name: 'Test Product' };
           const wrapper = shallowMount(ProductCard, {
               props: { product },
           });
           expect(wrapper.text()).toMatch(product.name);
       });
   });
   
3. **运行测试**：

      npm run test
   
通过这一路的测试，我们发现了不少 bug，还有助于团队成员理解组件的设计和功能。

## 5. 持续集成与部署

最后，持续集成与部署环节是我们项目中必不可少的一部分。我们选择了 GitHub Actions 来实现自动化部署，每当有新代码提交到主分支时，都会触发一系列的构建、测试和部署操作。

### GitHub Actions 配置示例

在项目根目录下创建一个 `.github/workflows/ci.yml` 文件，内容如下：

name: CI

on:
  push:
    branches:
      - main

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout code
        uses: actions/checkout@v2

      - name: Install dependencies
        run: npm install

      - name: Run tests
        run: npm run test

      - name: Build project
        run: npm run build

      - name: Deploy
        run: npm run deploy

通过这些配置，我们可以节省大量的手动操作时间，确保代码合并后不会破坏生产环境。

## 总结

在前端工程化的过程中，我们不仅仅是引入了新工具，更是在团队文化上产生了变化。每个人开始关注代码质量，考虑复用性，重视测试和自动化，这些都为我们的项目带来了显著的提升。

希望这些经验对正在进行前端工程化的小伙伴们有所帮助，欢迎一起交流！
